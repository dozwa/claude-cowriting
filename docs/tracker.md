## User stories and acceptance criteria

A criterion must hold on all three surfaces.

**S1 Claude cannot change my text** (tier 1; F8, F9, F10, F11, R2.1, R2.2). I ask for edits to my manuscript, so that the text stays mine.

- · S1.1: Every write attempt on an author file is refused, and the refusal names the file.
- · S1.2: Anything that gets through appears as a guard entry, and manuscript changes appear in the disclosure.

**S2 I can sign the disclosure** (tier 1; F13, F14, F15, F16, F17, F18, F19, R3.1, R4.1). I generate it before submission, so that it is true.

- · S2.1: Each prompt and answer of a session is in the log, with model and plugin version.
- · S2.2: Counts, categories, classifications and guard events match what happened.
- · S2.3: Unmarked AI prose and later log edits are either caught or stated as limits.

**S3 Claude helps without writing for me** (tier 1; F12, F13, R1.1, R1.4). I ask for prose, so that I see the tool keeps me the author.

- · S3.1: By default Claude declines and offers feedback or questions.
- · S3.2: If I insist, the text starts with `[AI-TEXT]`, is flagged, and is listed in the disclosure.

**S4 References are real** (tier 1; F32, F33, F34, R5.1, R5.2). I ask for sources, so that I cite nothing invented.

- · S4.1: No reference is shown without a verified DOI or URL or a bibliography citekey; others read `UNVERIFIED`.
- · S4.2: Wrong DOIs show as `MISMATCH` or `NOT FOUND`.

**S5 Pre-submission check** (tier 1; F20). I run `/cowrite:submit` before a draft leaves, so that nothing open slips through.

- · S5.1: Seeded problems all appear.
- · S5.2: It reports findings and does not declare readiness.

**S6 Get feedback** (tier 1b; F22, F23). I summon a persona, so that I see my text from its perspective.

- · S6.1: One progress line, located findings, no replacement text, briefing applied.

**S7 Read it** (tier 1b; F40, N2, N4). I open an input, so that I can take it in without noise.

- ✗ S7.1: The text appears once, as rendered Markdown. *(Seen failing in the VS Code test of 0.3.5, 2026-11-04)*
- · S7.2: The main action is visible without scrolling at the smallest supported pane.
- ✗ S7.3: Choices, reply, comment, links and text have a clear order of importance. *(Seen failing in the VS Code test of 0.3.5, 2026-11-04)*

**S8 Decide what I did with it** (tier 1; F16, F40, R3.2, N1). I classify an input, so that the record says what I did.

- · S8.1: One key or click records it; it leaves the open list and the counts drop.
- ✗ S8.2: It is clear when a comment is kept. *(Seen failing in the VS Code test of 0.3.5, 2026-11-04)*

**S9 Ask back** (tier 1b; F25, N3). I reply to a persona, so that we can settle a point.

- ✗ S9.1: I type and read the exchange in the thread. *(Seen failing in the VS Code test of 0.3.5, 2026-11-04)*
- · S9.2: The persona answers as a colleague; the log keeps the links; the appendix says "in reply to".

**S10 Keep what was settled** (tier 2; F26). I use Remember, so that a persona keeps it for the next run.

- · S10.1: Nothing is written before I save; at most two lines; the proposal is logged.

**S11 See what is open** (tier 1b; F38, F39, F42). I look at the pane or status line, so that I know what I still owe.

- · S11.1: All surfaces show the same count, which matches `ailog.py stats`.

**S12 Start a paper** (tier 1b; F1, F2, F5). I have never used this tool or git, and want a first review.

- · S12.1: From the README alone I reach a first review, without help, in a time we set after the first trial.

**S13 Return to a paper** (tier 1b; F3). I open it from anywhere, so that I can continue where I was.

- · S13.1: The guard, log and pane all point at that paper.

**S14 Update safely** (tier 2; F4). I update the plugin, so that I get fixes without risk to my paper.

- · S14.1: `upgrade` lists the gaps; `apply` leaves the manuscript, `party.md` and `scope.md` unchanged.

**S15 Use my tools** (tier 2; F6, F34, F35, F36). I write in LaTeX, Markdown or Word and export from my reference manager.

- · S15.1: Each format is readable, counted and guarded.

**S16 Live hints** (tier 2; F45). I pause while writing, so that I get short hints without asking.

- · S16.1: Only changed paragraphs are sent; at most 3 hints, 1 review a minute, 20 an hour.
- · S16.2: Each review is logged, and no sentence is rewritten.

**S17 Think it through** (tier 2; F28, F29, F30, F31). I use Socratic, structure, explain, language or consistency.

- · S17.1: Each skill keeps to its form: for example one question at a time, or corrections with the rule.

**S18 Know my progress** (tier 2; F46, F47). I look at Scope, so that I know how far the paper is.

- · S18.1: Numbers match a hand count; AI checks are logged; ticks I set myself win.

**S19 Motivation without rewarding AI** (tier 3; F48, F49). I look at Progress, so that my own writing is what counts.

- · S19.1: XP comes only from my words and transparency; asking the AI earns nothing.
